## 共識

- **賽道**：BFSI（核心是金流釣魚，社會效益好講），Retail & Commerce 備案。
- **目標用戶**：小賣家（蝦皮、露天、Carousell、Shopee 東南亞站），不做消費者端（已有 165、Whoscall、Gogolook、ScamShield）。
- **差異化**：跨平台（平台防詐只在站內跳警告，被帶到 LINE／FB 就管不到）、站在賣家這邊、直接給可回的話術。
- **MVP 做**：貼對話或上傳截圖（截圖只讀文字）→ Gemini Flash 結構化輸出（JSON schema：手法分類、紅旗句子、安全回覆）→ 兩個 function calling 工具（①網址信譽查詢，改用 **Web Risk API** ②網域冒用比對，純程式：punycode 轉回原字後與 shopee.tw／shopee.sg／carousell／ruten 白名單比字元差距）→ 判定卡 → 紅旗句子清單 → 一鍵複製安全回覆。
- **MVP 不做**：假轉帳截圖辨識（介面也不得出現「偵測偽造截圖」）、退貨詐騙、平台串接、登入、歷史紀錄、儀表板、聊天泡泡重現。
- **安全設計**：短網址不展開、直接列紅旗；後端只查網址、絕不開連結；安全回覆輸出後以程式再濾網址與帳號；服務端不記錄對話內容；Web Risk／Gemini 失敗或超配額一律灰卡。
- **介面（Dana）**：手機直向單畫面，白底，英文介面。由上到下：輸入區 → 四個步驟標籤（讀取文字／查網址／比對網域／完成判定）→ 判定卡 → 紅旗清單（原句＋原因＋工具標籤）→ 安全回覆＋一鍵複製。判定卡三態：紅「Scam red flags found」、琥珀「No red flags found」（固定小字「不代表安全，付款前請走平台內流程」）、灰「Can't determine」。綠色只用在安全回覆卡與複製按鈕。
- **3 分鐘影片分鏡**：0–20 秒痛點開場 → 20–90 秒 shopee-tw 改字釣魚案例、步驟亮起、紅卡與紅旗清單 → 90–115 秒複製安全回覆貼回聊天 → 115–145 秒正常買家（琥珀卡）＋ injection（被擋）→ 145–180 秒評測數字與社會效益。
- **Pitch 三句（Sandy）**：①小賣家在 LINE、FB、Carousell 被假買家丟釣魚連結，平台防詐管不到站外 ②賣家貼上對話，Gemini＋網址信譽查詢標出可疑句子、給可直接複製的安全回覆 ③站在賣家這邊、跨平台，回覆前 10 秒擋下。
- **商業模式**：個人賣家免費；長期 API 授權給開店平台與金流商（只當 pitch 願景）。不賣銀行（銷售週期與合規成本一人公司扛不起）。現階段只驗證「賣家願不願每月付小錢」。
- **評測集（33 則）**：20 則詐騙（8 釣魚連結、4 punycode／改字網域、3 短網址、5 站外付款話術）＋10 則正常（其中 3 則帶真 shopee.tw 連結測誤報）＋3 則 prompt injection；真實截圖另當盲測，不調 prompt；評測樣本不得與 prompt 範例重複。

- **里程碑**：9/25–9/29 找賣家案例；9/26 開工；9/29 晚盤點案例；9/30 前取得主辦回覆；10/5 後端吐出 JSON；10/9 功能凍結；10/10–10/11 錄影片；10/12 起只做 LineSleuth。

## 主要風險

1. **參賽規則**：一人或同一團隊能不能交兩件、隊友能不能重疊都還不確定。兩件都還卡在「至少 2 人」的組隊規定。
2. **拖垮 LineSleuth**：LineSleuth 還要 60–80 小時，這件佔掉 25 小時，時間互相擠壓。
3. **工時超支**：25 小時已經排滿，沒有餘裕；找賣家的時間還沒算進去。
4. **判斷的可信度**：
   - 網址信譽查不到不代表安全，因為新註冊的釣魚網域通常還沒被收錄。
   - 誤報會得罪真買家，漏報會讓賣家被騙錢。
   - prompt injection 可能讓詐騙訊息反過來操控判斷。
5. **隱私與肖像**：真實截圖含姓名、電話、帳號，必須有書面同意並打碼。影片不露平台 logo。
6. **被看成台灣本地題**：評審在新加坡，要放東南亞案例。
7. **拿不到真實案例**：徵集不到就會觸發停損。
